# PRD helptool

To make the most out of PRD, especially because often a large group is involved, you need to come prepared

Follow this help-tool to make sure you have collected the important information before you come to a PRD session. The responsibility is of the Product Owner.


## Agenda

* Explain what is the PRD about

## Goal

* Explain what is the expected outcome of the PRD

## Business Requirements

* Explain why you want to discuss a specific change
* Explain the business case, bring up the client / customer needs and try to bring up all the necessary requirements
* If relevant/doable, bring data to support the "why".

## Long-term Product vision

* Explain here how this product is meant to work in the future, so that we know how to solution it in a way that we won't have to re-code it from scratch. Think of all the future use-cases which need to be covered, even if they are not relevant for the MVP, and list them here.

## User Stories

* User stories should be short and powerful. Great video, to learn how to make them short and powerful, and why they should short

  <https://youtu.be/_gteHp-ZR9k?si=IuoDR2tIhDXpWUzI>

## MVP & POST-MVP

* Define which version will be done first, and which will be done later.
* List for each version (in detail for the first one, more draft for 2nd and later) which features will be included

## Implementation Strategy

* Break down big epics into smaller tasks
* Define in which order the tasks should be executed

## Notes

* Write action points , tag the people who should be responsible for doing certain things
* write down what you have agreed on during the meeting
