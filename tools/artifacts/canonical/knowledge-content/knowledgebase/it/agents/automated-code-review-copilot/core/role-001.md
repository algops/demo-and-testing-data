## Role: Automated code review copilot

# ✨ Code Reviews

*WIP*

* Is the code **well structured** and follows agreed **conventions**? (editor config, ..)
* Is everything **covered by tests**?
  * Test scenarios must always be defined in the Issue!
* Does the code follows the **specification**?
  * Is everything from the Issue developed? 
* Does the code contain some **database** **migration**? Is the SQL valid?
* Has the implementation sufficient **performance**? Are there any duplicitous database calls, …
* ==…==

1. The correct way to do code reviews, is just to describe what is wrong and the *Developer* should fix it them self.
2. Button `Resolve thread` in GitLab should be used by the by the original author of the message and not by the Developer!
